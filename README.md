## 🎯 Objective

## ✨ Features

The application includes:

- Start
- Stop
- Reset
- Lap

### Start

Starts the stopwatch and begins tracking elapsed time.

### Stop

Stops or pauses the current timing operation.

### Reset

# 5. Weather Application

## 📌 Project Overview

The Weather Application was the API-oriented project of the internship.

It demonstrates how a web application can communicate with an external weather API, retrieve information and dynamically display the returned data.

## 🎯 Objective

The main objective was to create a weather application capable of retrieving current weather information based on user input or location.

## ✨ Features

- Search weather by city
- Current-location option
- Weather API integration
- Dynamic data retrieval
- Temperature display
- Weather condition display
- Humidity display
- Wind-speed display

## 💻 Technologies Used

- HTML5
- CSS3
- JavaScript
- Weather API

## 🔧 Tools Used

- Visual Studio Code
- Web Browser
- GitHub

## 🏗️ Application Flow

The application follows a simple client-side data flow:

```text
User Input
    │
    ├── City Search
    │
    └── Current Location
           │
           ▼
     JavaScript Logic
           │
           ▼
       Weather API
           │
           ▼
    API Response Data
           │
           ▼
    JavaScript Processing
           │
           ▼
     Weather Interface
           │
           ├── Temperature
           ├── Condition
           ├── Humidity
           └── Wind Speed
🔹 Step 1 – User Input

The user can enter a city or use the current-location option.

🔹 Step 2 – API Request

JavaScript uses the selected input to request weather information from the Weather API.

🔹 Step 3 – Response Processing

The application receives the weather information and processes the returned data.

🔹 Step 4 – Dynamic Display

The relevant weather information is displayed on the webpage.

Problem

Web interfaces need to remain usable across different screen sizes.

Approach

Responsive CSS principles were applied and the webpages were tested at different screen sizes.

Learning

This improved understanding of responsive layout and adaptive UI design.

Challenge 2 – JavaScript Interaction
Problem

Interactive applications require user actions to trigger the correct behaviour.

Approach

JavaScript events and application logic were implemented and tested individually.

Learning

This strengthened understanding of event-driven programming.

Challenge 3 – Application Logic
Problem

Projects such as the Stopwatch and Tic-Tac-Toe require the application to maintain state and respond correctly to sequences of actions.

Approach

The functionality was divided into individual operations and repeatedly tested.

Learning

Challenge 4 – API Integration
Problem

Approach

The user input, API communication and returned data were checked during browser testing.

Learning
